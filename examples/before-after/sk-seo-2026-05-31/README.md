# Before / After — sk-seo.ru (2026-05-31)

Третий before/after-пример для global-design-skill. Тот же прод-сайт (личный бренд SEO-специалиста, тёмная тема, vanilla HTML/CSS/JS, без билд-шага), что и [sk-seo-2026-05-30](../sk-seo-2026-05-30/). Эта сессия строится **поверх** 260530, поэтому «before» для неё = состояние `after/` предыдущего примера.

Главное отличие от 260530: тот был **аудит-и-починка** (a11y, анти-слоп, чистка). Этот — **визуальный апгрейд**: введён новый язык бенто-сеток, единая система иконок и фотоконтент. Задеплоено на прод и верифицировано (`?v=202605310513`).

## Что в папке

- `after/` — 7 изменённых страниц × desktop (1440) + mobile (390): index, services, cases, about, contacts, tools, blog.
- `components/` — 12 крупных кадров ключевых паттернов (hero-бенто, спотлайт услуг, statement кейсов, meta-блок, career-intro, person-card, 3 пака иконок, иконки на tools/blog, единый blog-CTA, и кадр **живого прода** как доказательство деплоя).
- `DESIGN-DECISIONS.md` — таблица решений с привязкой к принципам/gate скила + заметки на обновление скила.

## Метод

Итеративно, по одной странице за раз, через профильный скилл `webapp-testing` (Playwright). **Каждая** страница после правок прогонялась через:
- горизонтальный overflow-чек (docW vs viewport) на 390/768/1280/1440,
- axe-core 4.10.2 (WCAG 2.0/2.1 A+AA) на тех же ширинах,
- визуальный контроль рендера (скриншот компонента), а не только «нет ошибок».

Итог: **0 axe-нарушений и 0 overflow на 9 страницах + выборке статей**. Деплой → smoke-тест прода (HTTP 200 + наличие разметки + 0 битых картинок + Playwright-рендер живых страниц).

## Введённые паттерны (новое для скила)

Все — на одном «бенто-языке»: ячейки разного размера в общей сетке, тонкий 1px-бордер, зелёный акцент на ключевой ячейке, мono-лейблы `// Метка`.

| Паттерн | Где | Суть |
|---|---|---|
| **Bento hero** | index | Имя+CTA, крупное фото, ячейки чисел и зелёная proof-ячейка («108M — аудит Avito») — доказательство масштаба **до скролла**, а не под фолдом |
| **Spotlight (featured-tariff)** | services | Зелёная якорная ячейка флагмана + портрет + trust-strip. **Price-anchoring**: дорогой флагман якорит, точечное выглядит доступным |
| **Statement-band** | cases | Зелёная ячейка с тезисом «От лендинга до 108M страниц» + 3 stat'а + кинематографичный портрет |
| **Editorial meta-spec** | cases | Под заголовком карточки — мono-триада `Ниша / Масштаб / Статус` с бордером сверху-снизу |
| **Career-intro** | about | Фото «за работой» + дисплей-подпись перед карьерной лентой |
| **Person-card** | contacts | Тёплый портрет + «отвечаю сам, без менеджеров» наверху колонки контактов — снижает барьер обращения |
| **Branded icon system** | blog/services/tools | 60 тематических SVG (emerald line-art) вместо generic lucide; имена ложатся 1:1 на темы (`entity-seo`, `robots-rules`, `core-web-vitals`…) |
| **Unified content CTA** | blog | Один inline-баннер + один финальный CTA, дописанный 12 статьям, у которых пути к конверсии не было |

## Анти-дубль как принцип контента (применён в cases)

Поле «Масштаб» в meta-блоке кейсов **не повторяет число** из заголовка и из метрик (иначе «420K» трижды на одной карточке — вода). Вместо числа — **tier** (Enterprise / Mid-market / SMB / Свой проект): новый сигнал, а не повтор. Это прямое применение Writing Standard («убирай лишнее») к структурной вёрстке, не только к прозе.

## Что подтвердил / чего просит скил (детали в DESIGN-DECISIONS.md)

1. **Verify-before-tile.** Прежде чем тиражировать новый паттерн на N страниц — собрать его на одной и реально прогнать axe+overflow+рендер. В этой сессии расхождение «сводка обещала скриншоты, которых нет на диске» поймано именно так; чужим обещаниям верификации доверять нельзя — только артефактам.
2. **Бенто-язык** — кандидат в blueprint скила как переиспользуемый рецепт (сетка-области + зелёная якорная ячейка + мono-лейбл).
3. **Price-anchoring через featured-ячейку** — паттерн для коммерческих страниц.
4. **Branded icon system** обходит «generic AI aesthetics»: тематические иконки под домен сильнее набора lucide. Кандидат в gate «иконки несут смысл, а не декор».
5. **Деплой-гигиена:** `cp -r blog/ img/` в deploy-скрипте без билд-шага тащит на прод бэкап-папки и сырьё — перед заливкой выносить мусор из deploy-путей (на SEO-сайте бэкап-HTML по предсказуемым URL = дубли-контент).
