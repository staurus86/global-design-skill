# Global Design Skill — Full Evolution Design
**Date:** 2026-05-25  
**Status:** Approved v2 (post-review)  
**Scope:** 4-phase evolution from static markdown skill to self-evolving design intelligence

---

## Problem Statement

Global Design Skill is domain-agnostic — it provides universal rules (typography, grid, states) but has no awareness of business niches. Given a request for an industrial equipment manufacturer vs. a bicycle shop vs. a tarot reader, it produces the same generic structure. The skill also lacks automated validation, has no learning capability, and requires manual file copying into context.

**Root cause:** The skill answers HOW to design, but not WHAT to design FOR WHOM.

**Goal:** Evolve the skill through 4 phases into a system that automatically detects the user's niche, retrieves or learns domain-specific rules, applies them, and improves over time based on feedback.

---

## Architecture Overview

```
Phase 1 — Content Layer         Static markdown files, works immediately
Phase 2 — MCP Static Server     Python tools, file-based sector context
Phase 3 — Learning Engine       Web scraping, pattern extraction, knowledge base
Phase 4 — SEDI Full             Perception → Cognition → Execution → Feedback → Evolution
```

Each phase is independently useful and non-breaking to the existing skill.

## Phase 1 — Content Layer

### industries/ — File Format

Every `industries/*.md` file includes YAML frontmatter for versioning:

```yaml
---
version: 1.0.0
last_updated: 2026-05-25
source: manual
stale_after_days: 90
---
```

- `source`: `manual` (written by humans) | `learned` (generated by Phase 3 engine)  
- `stale_after_days`: Phase 4 evolution engine uses this to schedule re-learning  
- `version`: bumped manually on significant content changes; Phase 3 checks this before overwriting

**Content structure per file:**

```markdown
## Sector Profile
- Decision pattern, risk level, key users

## Mobile-First Rules
- Specific mobile behaviour for this sector (e.g., bottom sheet booking for services,
  swipeable product gallery for b2c-products)

## Required Elements
- Mandatory page elements

## Banned Patterns
- What to never do in this sector

## Trust Signals
- How to build trust for this audience

## Conversion Path
- Awareness → Consideration → Decision → Action flow

## Typical Page Structure
- Ordered sections

## Quick Diagnosis
- 5 questions that determine the design pattern

## Disambiguation
- How this sector differs from overlapping sectors
```

**Sectors:**

| File | Sector | Example niches | Overlaps with |
|------|--------|---------------|---------------|
| `b2b-products.md` | B2B Products & Services | Industrial equipment, logistics, consulting | `tech-saas.md` for SaaS B2B |
| `b2c-products.md` | B2C Physical Products | Bicycles, electronics, furniture | — |
| `services.md` | B2C Services | Tarot, cleaning, fitness, legal | `health.md` for medical services |
| `content-media.md` | Content & Media | Blog, podcast, news, magazine | — |
| `education.md` | Education & Training | Courses, academies, corporate training | — |
| `health.md` | Health & Medicine | Clinics, telemedicine, wellness | `services.md` |
| `finance.md` | Finance & Fintech | Banking, insurance, crypto | — |
| `real-estate.md` | Real Estate | Agencies, developers, rentals | — |
| `travel.md` | Travel & Hospitality | Hotels, tours, restaurants | — |
| `tech-saas.md` | Tech & Startups | AI SaaS, hardware, IoT, developer tools | `b2b-products.md` for enterprise SaaS |
| `non-profit.md` | Non-profit & Civic | NGOs, foundations (sub-section: government portals) | — |
| `entertainment.md` | Entertainment & Culture | Games (sub: casual/AAA), streaming, events, sports | — |

**Disambiguation rules (b2b-products vs tech-saas):**  
Use `tech-saas.md` when the primary buyer is a developer or tech-savvy individual and the product is software. Use `b2b-products.md` when the buyer is procurement/engineering and the product is physical or requires RFQ.

**`non-profit.md`** covers both NGOs and government portals as sub-sections, with distinct rules for each (donor-focused vs citizen-focused). Split into separate files only if content exceeds 500 lines.

**`entertainment.md`** documents sub-niche rules inline: casual games vs AAA games have different conversion paths (free-to-play store vs pre-order), streaming vs live events have different urgency patterns.

**Integration:** `industries/_index.md` is referenced in `integrations/claude-code/CLAUDE.md` — AI reads the relevant sector file on any business-context request.

### patterns/states/ — Extended State System

The existing 9-state system (idle / hover / active / focus / disabled / loading / empty / error / success) is extended to 14 states. No existing states are replaced.

**`_decision-matrix.md` — When to use which state:**

| State | When to use | Duration | Example |
|-------|------------|----------|---------|
| `loading` (spinner) | Wait < 1s, or unknown data volume | Short | Form submit, auth |
| `skeleton` | Wait > 1s, structure is known in advance | Medium | Product list, feed |
| `partial-error` | Main content loaded, subset of data failed | Any | Table with 2/10 rows errored |
| `offline` | No network connection, PWA context | Until reconnect | Dashboard with cached data |
| `permission` | User lacks access to a feature or resource | Persistent | Locked plan feature |
| `rate-limit` | Too many requests, cooldown required | Timed | API quota reached |

**Rule:** `loading` and `skeleton` are mutually exclusive for the same element. Choose based on whether the content structure is predictable before data arrives.

**5 new state files:**

- **skeleton-states.md** — shimmer / pulse / structure preview variants, CSS implementation, when skeleton beats spinner.
- **partial-error-states.md** — inline error rows, degraded-mode banners, retry-per-row patterns.
- **offline-states.md** — sync queue UI, last-updated timestamp, reconnection flow.
- **permission-states.md** — no access vs upgrade required vs role-locked vs coming soon.
- **rate-limit-states.md** — countdown timer, retry-after display, quota progress bar.

---

### validators/ (3 files)

- **lighthouse-ci.md** — performance budgets (LCP < 2.5s, CLS < 0.1, FID < 100ms), CI config.
- **axe-core.md** — a11y testing thresholds, Jest/Playwright setup.
- **bundle-analyzer.md** — size limits per component, tree-shaking checklist.

### feedback/ (2 files)

- **gate-8-tracker.md** — log template for "developer asked a question after handoff".
- **iteration-log.md** — template for recording iteration count before design acceptance.

## Phase 2 — MCP Static Server

**Location:** `mcp-server/`  
**Tech:** Python 3.11+, `fastmcp`, `markdown-it-py`  
**Purpose:** Thin layer between `industries/` files and AI — no database, no state

### Graceful Degradation

```python
try:
    import fastmcp
    FASTMCP_AVAILABLE = True
except ImportError:
    FASTMCP_AVAILABLE = False
    # Fallback: expose tools as plain Python functions
    # Claude Code can call them via subprocess if MCP unavailable
```

If `~/.global-design-skill/` is read-only, all write operations log a warning and skip silently — the server remains functional for reads.

### 5 MCP Tools

All tools return `str` (JSON-encoded). `classify_niche` returns a JSON string, not a raw dict, for consistency with the MCP protocol.

```python
list_sectors() -> str
# Returns JSON: [{"sector": "b2b-products", "description": "...", "examples": [...]}, ...]

classify_niche(query: str) -> str
# Returns JSON: {"sector": "b2b-products", "confidence": 0.9, "alternatives": [...]}
# Never returns a raw dict — always JSON string

get_sector_context(sector: str, niche: str = None) -> str
# Returns full context from industries/*.md
# Includes frontmatter: version, last_updated, source

check_banned_patterns(sector: str, content: str) -> str
# content = plain text design description (not HTML)
# Returns JSON: {"violations": [...], "warnings": [...]}

get_quick_diagnosis(who_pays: str, decision_type: str, risk_level: str,
                    choice_type: str, user_value: str) -> str
# Returns JSON: {"sector": "...", "pattern": "...", "rationale": "..."}
```

### Testing Strategy

`mcp-server/tests/` contains:

- **`test_classify_niche.py`** — parametrised tests over `fixtures/sample_queries.json` (50+ queries across all 12 sectors, expected output included). Passes if accuracy ≥ 85%.
- **`test_sector_context.py`** — asserts that every `industries/*.md` file parses without error, frontmatter is valid, required sections present.
- **`fixtures/sample_queries.json`** — ground truth dataset: `{"query": "...", "expected_sector": "...", "expected_confidence_min": 0.7}`.

Run with: `python -m pytest mcp-server/tests/`

### Data Flow

```
AI request → classify_niche() → get_sector_context() → industries/b2b-products.md
                                                       ↑
                                              plain markdown file,
                                              editable by hand
```

## Phase 3 — Learning Engine

**Location:** `learning/`  
**Purpose:** When a niche is not in `industries/`, automatically find references, extract patterns, and save to local knowledge base

### Storage Limits and TTL

Enforced in `knowledge_base.py`:

```python
MAX_REFERENCES_PER_NICHE = 10
CACHE_TTL_DAYS = 30          # scraped HTML cache
STALE_THRESHOLD_DAYS = 90    # when to re-learn a niche (matches frontmatter default)
MAX_STORAGE_MB = 500         # total ~/.global-design-skill/ cap
```

If `MAX_STORAGE_MB` is reached, the LRU niche (lowest `usage_count + recency` score) is evicted first.

### 5 Modules

**`sector_classifier.py`**  
Keyword-weighted detection across 12 sectors. Returns `{"sector": str, "confidence": float, "alternatives": list}`. Confidence < 0.5 triggers a clarification prompt to the user before proceeding.

**`pattern_extractor.py`**  
Parses HTML/CSS, extracts: layout structure, components, trust signals, conversion elements. Also checks `industries/*.md` frontmatter `version` — if the static file is newer than the scraped data, extraction result is flagged as `potentially_outdated`.

**`ethical_scraper.py`**  
- `robots.txt` compliance + `noindex` directive respect (does not index pages marked noindex)  
- Rate limiting: 10 requests/minute  
- User-Agent: `GlobalDesignSkill-Bot/1.0 (Learning/Reference Collection)`  
- Note: outgoing HTTP requests mean target servers see request logs — this is expected and disclosed in `mcp-server/README.md`

**`gap_detector.py`**  
Compares extracted patterns against `industries/*.md`. Returns missing elements, outdated patterns, and a `suspicion_flag` when learned patterns diverge significantly from static rules (see Conflict Resolver below).

**`knowledge_base.py`**  
JSON storage at `~/.global-design-skill/knowledge/`. Storage directory created with `chmod 700` on Unix / restricted ACL on Windows at first write. Schema:

```json
{
  "sector": "b2b-products",
  "niche": "industrial-pumps",
  "version": "1.0.0",
  "source": "learned",
  "confidence_score": 0.85,
  "usage_count": 0,
  "success_rate": 0.0,
  "learned_at": "2026-05-25T00:00:00Z",
  "last_updated": "2026-05-25T00:00:00Z",
  "stale_after_days": 90,
  "suspicion_flag": false,
  "patterns": { "layout": [], "components": [], "visual": [], "interaction": [] },
  "rules": {
    "required_elements": [],
    "banned_patterns": [],
    "trust_signals": [],
    "conversion_elements": []
  },
  "references": [
    {"url": "...", "quality_score": 0.9, "scraped_at": "2026-05-25T00:00:00Z"}
  ]
}
```

### 2 New MCP Tools (extends Phase 2)

```python
learn_from_reference(url: str, sector: str = None, niche: str = None) -> str
# Scrapes site, extracts patterns, saves to knowledge_base
# Returns JSON: {patterns, gaps, suspicion_flag, references_count}

get_or_learn_sector(sector: str, niche: str) -> str
# 1. Check industries/*.md (static)
# 2. Check knowledge_base (learned)
# 3. If not found → auto-trigger learn_from_reference on top sites
# Guaranteed to return context
```

### Conflict Resolver (Static vs Learned)

When `industries/*.md` and `knowledge_base` disagree, `cognition.py` applies this priority:

```
1. User override        — explicit instruction in the current session
2. Local knowledge base — learned + validated (success_rate > 0.6, suspicion_flag = false)
3. industries/*.md      — static, manually curated
4. Generic rules        — fallback from existing skill files
```

**Suspicion flag:** raised in `gap_detector.py` when a learned pattern contradicts a static rule by > 40% (e.g., static says "RFQ form required", learning found 0 of 10 scraped sites have it). Flagged niches are surfaced to the user: *"Learned patterns for this niche differ significantly from our static rules. Review recommended before applying."*

The flag does NOT block usage — it informs the user and schedules a manual review task in `feedback/`.

## Phase 4 — SEDI Full Architecture

**Location:** `sedi/`  
**Purpose:** Orchestrates all layers, adds personalization through pattern weights, feedback loop, and periodic evolution

### 6 Modules

**`perception.py` — Request Analysis**

```python
@dataclass
class RequestAnalysis:
    intent: Literal["create", "improve", "audit", "learn", "compare"]
    sector: str
    niche: str
    context: dict    # has_existing_design, has_reference, has_constraints
    emotions: dict   # urgent, frustrated, confused
    constraints: dict  # budget, timeline, tech_stack, style
```

Confidence < 0.5 on sector detection → perception returns `sector = "unknown"` and triggers a clarifying question rather than guessing.

**`cognition.py` — Decision Making**

Knowledge lookup follows the Conflict Resolver priority defined in Phase 3.

Blueprint selection by intent:
- `create` → `blueprints/landing-page-from-scratch.md` (or sector-appropriate)
- `improve` → `blueprints/redesign-existing-page.md`
- `audit` → relevant checklist

Pattern selection applies weights with **exploration_rate = 0.10**: 10% of the time, a lower-weight pattern is selected for testing instead of the top-weight one. This prevents the system from converging on a local optimum.

**`execution.py` — Design Generation**

Applies blueprint + patterns + rules → structured design output.  
Runs Quality Gates validation before returning.  
Each decision cites its source: *"RFQ form required by b2b-products rules, confirmed by Grundfos.com reference (learned 2026-05-25)"*

**`feedback_engine.py` — Learning from Interaction**

Explicit signals: rating 1-5, liked/disliked patterns, comments  
Implicit signals: `revision_count > 3` → pattern underperforming  
Weight update: ±10% per interaction, capped at [0.1, 2.0]

**Decay:** patterns unused for 30+ days have their weight multiplied by 0.95 per week until they reach 1.0 (neutral). Prevents stale high-weight patterns from permanently dominating.

**Cold start:** for niches with < 5 interactions, weights default to 1.0 for all patterns. No statistical inference is attempted until the minimum interaction threshold is met.

**User control commands (MCP tools):**

```python
forget_niche(sector: str, niche: str) -> str
# Deletes knowledge_base entry for this niche

reset_weights(sector: str = None) -> str
# Resets all pattern weights to 1.0 for a sector (or globally)

list_learned_niches() -> str
# Returns all niches in knowledge_base with confidence + staleness info
```

**`evolution.py` — Periodic Self-Improvement**

Weekly cycle:
1. Calculate `effectiveness_score = success_rate × confidence` per niche
2. Re-train niches with `effectiveness_score < 0.5`
3. Check `last_updated` against `stale_after_days` — schedule re-learning if exceeded
4. Handle dead references: if a scraped reference URL returns 404, mark reference inactive and reduce niche confidence proportionally
5. Identify successful pattern combinations → generate composite patterns
6. Log all changes to `local_store/evolution_log/`

**`local_store/` — Personal Knowledge Base**

```
~/.global-design-skill/          (chmod 700 on Unix)
├── knowledge/
├── weights/
├── feedback/
├── evolution_log/
└── metrics/
    ├── baseline_accuracy.json   captured on first SEDI activation
    ├── current_accuracy.json    updated after every evolution cycle
    └── improvement_rate.json    delta: current - baseline, per sector
```

### SEDI Baseline Metrics

On first activation, `evolution.py` runs a baseline measurement:
- 20 sample queries (drawn from `mcp-server/tests/fixtures/sample_queries.json`)
- Records: sector classification accuracy, pattern relevance score (user rating average), iteration count to acceptance
- Saved to `metrics/baseline_accuracy.json`

After each weekly cycle, `current_accuracy.json` is updated. `improvement_rate.json` shows the delta. This answers "did SEDI get better?"

### SEDI Principles

- **Local-only storage:** All knowledge files stay on the user's machine
- **Transparent:** Every decision cites its source and confidence score
- **Controllable:** `forget_niche()`, `reset_weights()`, and direct JSON editing are all valid
- **Additive:** Each phase works without the next; SEDI enhances but does not replace

## Security & Privacy

**Outgoing requests (Phase 3):** `ethical_scraper.py` makes HTTP requests to reference sites. Target servers see these requests in their access logs — this is unavoidable and is disclosed in `mcp-server/README.md`. The scraper identifies itself honestly via User-Agent.

**`robots.txt` and `noindex`:** both are respected. Pages disallowed in `robots.txt` or marked `noindex` are skipped.

**Local storage permissions:**  
- Unix: `~/.global-design-skill/` created with `chmod 700`  
- Windows: directory created with restricted ACL (current user only)  
- No encryption at rest — knowledge files are plain JSON, intended to be human-readable

**MCP server logs:** IDE integrations (Claude Code, Cursor) may log MCP tool calls. Users should review their IDE's logging settings if query privacy is a concern. The MCP server itself does not write logs by default.

**No telemetry:** SEDI collects no usage metrics outside `~/.global-design-skill/`. No data is sent to any remote endpoint by this system.
