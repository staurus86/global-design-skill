# Pattern — Notifications and Alerts

> Notifications communicate system state. There are four types, and the choice between them is not aesthetic — it's determined by urgency, persistence, and where the user's attention needs to be. Using the wrong type (a modal for an error, a toast for a blocking failure) is a UX error, not a style decision.

---

## The Four Types

| Type | Urgency | Persistence | Blocks action? | When to use |
|---|---|---|---|---|
| **Toast** | Low–Medium | Auto-dismiss (3–5s) | No | Confirmation of completed action |
| **Banner** | Medium | Until dismissed | No | Page-level status, feature announcements |
| **Inline alert** | Medium–High | Until resolved | No | Form errors, field-specific feedback |
| **Dialog** | High | Requires decision | Yes | Blocking errors, destructive confirmations |

**Decision tree:**
```
Did the user trigger this?
  Yes → Toast (success) or inline error (failure)
  No  → Banner (page-level) or dialog (blocking)

Is the user's data at risk?
  Yes → Dialog with explicit confirmation
  No  → Toast or banner

Can the user continue without resolving it?
  Yes → Toast or banner
  No  → Dialog or inline error that disables the form
```

## Pattern 1 — Toast Notifications

**Context:** Background confirmations. User completed an action and needs a quick acknowledgment. Appears at the bottom-right, auto-dismisses in 4 seconds, stacks if multiple.

```html
<!-- Toast container: fixed position, renders all active toasts -->
<div
  class="toast-region"
  aria-label="Notifications"
  aria-live="polite"
  aria-atomic="false"
  role="region"
>
  <!-- Toasts injected here by JS -->
</div>
```

```html
<!-- Individual toast (generated by JS) -->
<div
  class="toast toast--success"
  role="status"
  aria-live="polite"
  aria-atomic="true"
>
  <svg class="toast__icon" aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5">
    <path d="M22 11.08V12a10 10 0 1 1-5.93-9.14"/>
    <polyline points="22 4 12 14.01 9 11.01"/>
  </svg>
  <div class="toast__content">
    <p class="toast__title">Changes saved</p>
    <!-- Optional: action link -->
    <a href="/deployments/abc" class="toast__action">View deployment →</a>
  </div>
  <button type="button" class="toast__dismiss" aria-label="Dismiss notification">
    <svg aria-hidden="true" width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5"><path d="M18 6 6 18M6 6l12 12"/></svg>
  </button>
  <!-- Progress bar showing auto-dismiss countdown -->
  <div class="toast__progress" aria-hidden="true"></div>
</div>
```

```js
class ToastManager {
  constructor(region) {
    this.region = region
    this.queue = []
  }

  show({ type = 'info', title, action, duration = 4000 } = {}) {
    const toast = document.createElement('div')
    toast.className = `toast toast--${type}`
    toast.setAttribute('role', 'status')
    toast.setAttribute('aria-live', 'polite')
    toast.setAttribute('aria-atomic', 'true')

    toast.innerHTML = `
      <svg class="toast__icon" aria-hidden="true" ...></svg>
      <div class="toast__content">
        <p class="toast__title">${title}</p>
        ${action ? `<a href="${action.href}" class="toast__action">${action.label}</a>` : ''}
      </div>
      <button type="button" class="toast__dismiss" aria-label="Dismiss">×</button>
      <div class="toast__progress" aria-hidden="true"></div>
    `

    this.region.append(toast)

    // Animate progress bar
    const progress = toast.querySelector('.toast__progress')
    progress.style.animationDuration = `${duration}ms`
    progress.classList.add('running')

    const dismiss = toast.querySelector('.toast__dismiss')
    const remove = () => {
      toast.classList.add('toast--exiting')
      toast.addEventListener('animationend', () => toast.remove(), { once: true })
    }

    dismiss.addEventListener('click', remove)

    // Pause auto-dismiss on hover
    let timer = setTimeout(remove, duration)
    toast.addEventListener('mouseenter', () => clearTimeout(timer))
    toast.addEventListener('mouseleave', () => { timer = setTimeout(remove, 1500) })

    // Entry animation
    requestAnimationFrame(() => toast.classList.add('toast--entering'))
  }
}

const toasts = new ToastManager(document.querySelector('.toast-region'))

// Usage
toasts.show({ type: 'success', title: 'Deploy started', action: { href: '/deploy/123', label: 'View logs' } })
toasts.show({ type: 'error',   title: 'Build failed — 3 tests failed' })
toasts.show({ type: 'info',    title: 'Team member invited', duration: 5000 })
```

## Pattern 2 — Banner Alert

**Context:** Page-level status that persists until the user dismisses it or the condition resolves. Sits at the top of the content area (not covering navigation).

```html
<!-- Warning banner: user has unpaid invoice -->
<div
  class="banner banner--warning"
  role="alert"
  aria-live="polite"
  aria-atomic="true"
>
  <svg class="banner__icon" aria-hidden="true" width="18" height="18" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5">
    <path d="M10.29 3.86L1.82 18a2 2 0 0 0 1.71 3h16.94a2 2 0 0 0 1.71-3L13.71 3.86a2 2 0 0 0-3.42 0z"/>
    <line x1="12" y1="9" x2="12" y2="13"/>
    <line x1="12" y1="17" x2="12.01" y2="17"/>
  </svg>
  <p class="banner__message">
    Your trial ends in <strong>3 days</strong>.
    <a href="/billing" class="banner__link">Upgrade now to keep your data.</a>
  </p>
  <button type="button" class="banner__dismiss" aria-label="Dismiss notice">
    <svg aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5"><path d="M18 6 6 18M6 6l12 12"/></svg>
  </button>
</div>

<!-- Error banner: action required -->
<div class="banner banner--error" role="alert" aria-live="assertive" aria-atomic="true">
  <svg class="banner__icon" aria-hidden="true" ...></svg>
  <p class="banner__message">
    Your payment method failed. <a href="/billing" class="banner__link">Update card to restore access.</a>
  </p>
  <!-- No dismiss — must be resolved -->
</div>

<!-- Info banner: feature announcement -->
<div class="banner banner--info" role="status" aria-live="polite">
  <svg class="banner__icon" aria-hidden="true" ...></svg>
  <p class="banner__message">
    New: Deploy previews are now available for all branches.
    <a href="/docs/previews" class="banner__link">Learn how to enable them.</a>
  </p>
  <button type="button" class="banner__dismiss" aria-label="Dismiss">×</button>
</div>
```

## Pattern 3 — Inline Alert

**Context:** Feedback tied to a specific section of the page. Form validation summary, API error below a field group, info box within a settings section.

```html
<!-- Inline success: after saving settings -->
<div class="alert alert--success" role="status" aria-live="polite">
  <svg class="alert__icon" aria-hidden="true" width="16" height="16" ...><!-- check --></svg>
  <div class="alert__body">
    <p class="alert__title">API key saved</p>
    <p class="alert__desc">Changes take effect on next deployment.</p>
  </div>
</div>

<!-- Inline error: server-side form rejection -->
<div class="alert alert--error" role="alert" aria-live="assertive">
  <svg class="alert__icon" aria-hidden="true" width="16" height="16" ...><!-- x-circle --></svg>
  <div class="alert__body">
    <p class="alert__title">Could not save changes</p>
    <p class="alert__desc">
      The domain <strong>app.example.com</strong> is already in use by another project.
    </p>
  </div>
</div>

<!-- Inline info: advisory, non-blocking -->
<div class="alert alert--info">
  <svg class="alert__icon" aria-hidden="true" width="16" height="16" ...><!-- info --></svg>
  <div class="alert__body">
    <p class="alert__desc">
      Changes to environment variables require a redeploy to take effect.
    </p>
  </div>
</div>
```

## Notification System — aria-live Wiring

All dynamic notifications require `aria-live` regions to be announced by screen readers. The region must exist in the DOM before content is injected — screen readers only pick up changes within pre-existing live regions.

```html
<!-- Add to page layout — before any content that might inject notifications -->
<div id="toast-announcer"  aria-live="polite"   aria-atomic="true" class="sr-only"></div>
<div id="alert-announcer"  aria-live="assertive" aria-atomic="true" class="sr-only"></div>
```

```js
// Announce to screen reader without showing visual toast
function announce(message, priority = 'polite') {
  const el = document.getElementById(
    priority === 'assertive' ? 'alert-announcer' : 'toast-announcer'
  )
  el.textContent = ''
  requestAnimationFrame(() => { el.textContent = message })
}

// Usage alongside visual toast
toasts.show({ type: 'success', title: 'Deploy started' })
announce('Deploy started')

// For errors (assertive — interrupts screen reader immediately)
toasts.show({ type: 'error', title: 'Build failed' })
announce('Error: Build failed', 'assertive')
```

## Notification Acceptance Criteria

```
[ ] Type matches urgency: toast / banner / inline / dialog — no wrong type used
[ ] Toast: aria-live="polite" region, auto-dismiss 3–5s, pauses on hover
[ ] Toast: stacks correctly if multiple fire simultaneously
[ ] Toast: dismiss button with aria-label
[ ] Banner: sits below navigation, full width, appropriate role (alert vs status)
[ ] Banner: dismissible banners store dismissed state in localStorage
[ ] Inline alerts: appear adjacent to the relevant content
[ ] All alerts: icon + color + text (never color alone)
[ ] Success: "polite" live region; Error: "assertive" live region
[ ] prefers-reduced-motion: entry/exit animation removed, opacity only
[ ] Mobile: toasts full-width, respect safe-area-inset-bottom
[ ] Screen reader: sr-only live region announces messages
```
